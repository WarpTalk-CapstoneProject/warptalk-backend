Scope: static audit against the real codebase under `warptalk-backend` and `warptalk-web`. Report text and old `_worktrees` files were used only to identify the rule list, not as implementation evidence.

Status legend:

- `Implemented`: code path and/or tests support the business rule.
- `Partial`: important enforcement exists, but at least one clause is missing, weakly enforced, or untested.
- `Future-only`: rule is explicitly proposed/future or has only foundation code, not shipped end-to-end behavior.
- `Gap`: evidence shows behavior diverges from the rule.
- `Not found`: no meaningful implementation evidence found in the audited code.

## Summary

- Total rules audited: 97.
- High-confidence implemented: 64.
- Partial: 26.
- Future-only: 4.
- Gaps / not found: 3.

Main gaps/partials to fix before treating the SRS table as fully implemented:

- `BR-02`: registration still issues a session before email verification.
- `BR-04`: Google account creation/linking does not hard-reject every unverified Google email identity.
- `BR-34`: invitation resend replaces token material but does not mark the previous invitation/token as `REPLACED`.
- `BR-74`: public plan listing filters `DeletedAt` only, so deactivated plans may still be customer-selectable.
